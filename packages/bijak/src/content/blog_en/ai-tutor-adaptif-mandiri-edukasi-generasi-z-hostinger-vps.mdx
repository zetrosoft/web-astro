## System Architecture: Integrating LLM, RAG, and Vector Databases

To build an AI assistant that delivers accurate contextual guidance rather than generic hallucinated answers, a specialized tech stack is required. The foundation relies on **Retrieval-Augmented Generation (RAG)**, connecting an open-source Large Language Model to custom curriculum knowledge bases.

The processing pipeline consists of three core components:
1. **Ingestion & Embedding Layer**: Converting PDF or Markdown lecture notes into dense vector embeddings via lightweight models like `bge-small-en-v1.5` or `nomic-embed-text`.
2. **Vector Storage**: Storing spatial text embeddings for sub-second similarity retrieval. When designing a [scalable personal AI lab architecture](/en/blog/arsitektur-lab-ai-personal-edutech-skalabel/), selecting a lightweight vector engine is essential.
3. **Inference Engine**: Augmenting user prompts with relevant retrieved context before feeding them to the local LLM.

To query vector embeddings efficiently without overloading system RAM, developers can leverage the [self-hosting efficiency of pgvector database](/en/blog/pgvector-self-host-efisiensi-coolify-hostinger-vps-vs-managed-cloud/) directly inside PostgreSQL.
