Processing Large Language Model (LLM) inference requests directly on the Node.js or Python main thread causes severe event loop blocking. When a single inference task takes 4,500 ms, CPU utilization spikes to 100%, triggering HTTP 504 Gateway Timeouts for all concurrent users.

The industry-standard fix is decoupling heavy execution from the main HTTP layer using asynchronous task queues. BullMQ, backed by Redis, provides robust queue management designed to offload heavy AI processing to background workers without compromising API responsiveness.

### Tactical Checklist for BullMQ Production Setup

1. **Configure Worker Concurrency**: Set `concurrency: 5` to `10` per worker instance to align with external LLM API rate limits.
2. **Enable Automatic Job Cleanup**: Set `removeOnComplete: { age: 3600, count: 1000 }` and `removeOnFail: { age: 86400 }` to avoid Redis RAM saturation.
3. **Implement Exponential Backoff**: Define `attempts: 5` with `backoff: { type: 'exponential', delay: 2000 }` to seamlessly recover from transient API timeouts.
