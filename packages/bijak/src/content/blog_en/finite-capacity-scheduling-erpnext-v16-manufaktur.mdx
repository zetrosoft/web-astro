Indonesian manufacturing industry reports heading into 2026 highlight a concerning trend: the surge in product customization requests (*high-mix, low-volume*) frequently collides with actual capacity on the factory floor. Operational executives often find pristine production schedules disrupted within hours due to machine constraints, unpredicted downtime, or sequence setup conflicts. The root cause lies in the limitation of conventional planning systems that assume machine capacity is virtually unlimited (*infinite capacity*).

By default, standard ERP systems map work orders without accounting for the actual hourly workstation load at any given moment. When multiple jobs pile up at a critical machine, Work-in-Progress (WIP) inventory explodes and lead times inflate. Resolving this dilemma requires implementing Finite Capacity Scheduling (FCS) as a crucial foundation for Industry 4.0 transformation in complex manufacturing environments.

### Paradigm Shift: Infinite Planning vs. Finite Capacity Scheduling

In modern operational management, utilizing the [ERPNext v16 manufacturing module for BOM and Work Orders](/en/blog/panduan-modul-manufaktur-erpnext-v16-bom-work-order/) provides a solid foundation. However, as production routing complexity scales, standard infinite-capacity scheduling must evolve into a finite capacity approach.

Infinite capacity planning assumes workstations are always available whenever a Work Order is generated. Conversely, Finite Capacity Scheduling treats time, machine capacity, and operator availability as absolute boundaries. The system automatically shifts schedules forward or backward based on actual open production slots.

The table below illustrates the fundamental differences between these two scheduling approaches within a manufacturing ecosystem:

| Evaluation Parameter | Infinite Capacity Scheduling (Standard ERPNext v16) | Finite Capacity Scheduling (Advanced FCS) |
| :--- | :--- | :--- |
| **Machine Capacity Assumption** | Unlimited (accumulates load without time constraints) | Finite (strictly bound by working hours & maintenance) |
| **Bottleneck Handling** | Manual resolution by planners after queueing occurs | Automated deduction of capacity & sequence shifting |
| **Setup Time Management** | Assumed static or frequently ignored | Dynamic based on product attribute sequence (color, size, material) |
| **On-Time Delivery (OTD) Accuracy** | Prone to delays due to schedule over-promising | Highly accurate based on real-time slot allocation |
| **WIP Inventory Level** | High (material accumulation upstream of bottleneck) | Low (materials pulled per machine readiness / JIT) |
| **Dynamic Rescheduling** | Requires manual adjustment of every Work Order | Instant algorithmic execution via event triggers |

### Frappe Framework Architecture for FCS Algorithms

The flexibility of Frappe Framework v16 allows developers to construct finite capacity algorithms directly within the manufacturing module structure or interface with external Advanced Planning and Scheduling (APS) engines. Designing this core logic relies on three fundamental components:

1. **Constraint Matrix DocType Construction**: Custom attributes created on Workstations to define maximum parallel workload, cooling times, and tool/die changeover matrices.
2. **Dynamic Slot Allocation Logic**: Leveraging heuristic rules or Constraint Satisfaction Programming (CSP) via Python Server Scripts to sequentially distribute Work Orders according to customer priority and target delivery dates.
3. **Event-Driven Rescheduling**: Employing Frappe Background Jobs (*Redis/RQ*) to automatically trigger schedule recalculations upon unexpected events such as machine breakdowns or raw material delay.

### Tactical Implementation Checklist & Risk Mitigation

To ensure a smooth transition from conventional scheduling to Finite Capacity Scheduling without operational friction, IT managers and plant directors can apply the following mitigation checklist:

- [ ] **Validate Standard Times Accuracy (Routing & Operations)**: Verify that Cycle Times and Setup Times in every BOM reflect actual floor conditions.
- [ ] **Identify Core Bottlenecks (Constraint Workstations)**: Determine the 20% critical machines limiting 80% of plant throughput to prioritize under finite constraints.
- [ ] **Test Scheduling Algorithms in Staging**: Execute schedule recalculations simulations using actual production data snapshots prior to live deployment.
- [ ] **Train Shop Floor Operators**: Educate floor workers to rigorously log start/stop actions via the Shop Floor Workbench terminal to keep workstation load metrics current.
