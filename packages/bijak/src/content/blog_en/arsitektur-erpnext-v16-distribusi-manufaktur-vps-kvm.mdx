## 3. Production Infrastructure Blueprint: Running ERPNext v16 on Independent KVM VPS

Processing thousands of daily inventory mutations with sub-second response times requires careful server infrastructure planning. ERPNext v16 relies on MariaDB with optimized InnoDB engine parameters, Redis instances for session caching and background job worker queues, and Node.js for real-time WebSocket communication.

Under production workloads, the underlying host machine requires high single-core CPU clock speeds and low-latency NVMe storage to prevent perpetual inventory valuation recalculations and trial balance aggregations from encountering I/O bottlenecks.

For production clusters supporting 25 to 60 concurrent users, deploying containerized instances on high-performance virtual private servers like [Hostinger KVM 4 VPS](https://www.hostinger.com/id?REFERRALCODE=6X5PUTERARQL) provides exceptional throughput. Featuring 4 dedicated vCPU cores, 16 GB of RAM, and 200 GB of pure NVMe storage on a 300 Mbps uplink, this configuration gives MariaDB ample overhead to allocate an 8 GB `innodb_buffer_pool_size` without risking Out-Of-Memory (OOM) termination. When configuring your compute instances, you can apply the official discount coupon **`6X5PUTERARQL`** during checkout for substantial recurring savings on multi-year hosting tiers.

Here is a hardened `docker-compose.yml` baseline designed for production ERPNext v16 container deployment:

```yaml
version: "3.8"

services:
  erpnext-backend:
    image: frappe/erpnext:v16.0.0
    restart: unless-stopped
    environment:
      - DB_HOST=mariadb
      - DB_PORT=3306
      - REDIS_CACHE=redis-cache:6379
      - REDIS_QUEUE=redis-queue:6379
    volumes:
      - sites-vol:/home/frappe/frappe-bench/sites
      - logs-vol:/home/frappe/frappe-bench/logs
    depends_on:
      - mariadb
      - redis-cache
      - redis-queue

  mariadb:
    image: mariadb:10.11
    restart: unless-stopped
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
      - --innodb-file-per-table=1
      - --innodb-buffer-pool-size=8G
    environment:
      - MYSQL_ROOT_PASSWORD=${DB_ROOT_PASSWORD}
    volumes:
      - mariadb-data:/var/lib/mysql

  redis-cache:
    image: redis:7-alpine
    restart: unless-stopped

  redis-queue:
    image: redis:7-alpine
    restart: unless-stopped

volumes:
  sites-vol:
  logs-vol:
  mariadb-data:
```

### Essential MariaDB Tuning Parameters for Transactional Throughput:
* **`innodb-buffer-pool-size=8G`**: Caches up to 50% of the host machine's total 16 GB memory footprint, ensuring critical inventory ledger tables (`tabBin`, `tabStock Ledger Entry`) stay permanently hot in memory.
* **`character-set-server=utf8mb4`**: Guarantees full Unicode compliance and eliminates encoding discrepancies across multilingual item descriptions.
